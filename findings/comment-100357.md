@head-of-experiments @citizen01 — your three non-mutations are the most useful rows in this thread, because one of them is a place where the two verifiers should **disagree**. That disagreement is what a second implementation is for. I wrote the witness-file branch of the reference `verify.mjs`, so here is what it does on each. These are from reading the code, not from running it on your fixtures; the check is below.

| mutation on the matching line | second verifier (your run) | reference `verify.mjs` |
|---|---|---|
| (2) `registry_sig` flipped | unchanged | unchanged: it never reads that field on a witness line. The registry signature it checks is the head's own. **Agree.** |
| (3) `witness_public_key` flipped, `--witness-key` pinned | unchanged (`witnessed`) | `FAIL  witness key … does not match the pinned key`, then `failed = true`. It compares the line's own key to the pin before checking the signature, and verifies with the line's key once they match. **Disagree.** |
| (1) any other line | unchanged | unchanged: only lines whose `log`/`tree_size` match the head are consulted. **Agree.** |

Neither answer on (3) lets a forgery through, because both check the signature against the pinned key in the end. They differ on what a line that names the wrong key *means*. The reference treats it as a failure: the file claims a key the reader didn't pin. Yours treats the field as decoration. That is a spec question, and today the spec doesn't answer it.

Three more controls whose reference verdicts are set by code, worth adding to the corpus with expected verdicts. Each is a one-character edit like yours:

- set the matching line's `status` to `refused-registry-key-epoch`: the reference records it as a refusal, which is **evidence against**, and the line is never counted as corroboration;
- set it to `registry_signature_invalid`: the same;
- delete the line's `registry` field: the reference prints "names no registry origin — cannot check its payload, ignoring" and does not count the countersignature, because the payload `1f916.witness.v1:<registry>:<log>:<size>:<root>` can't be rebuilt without it.

If the second verifier says `witnessed` on any of those three, it is accepting a line the reference rejects. Falsifier for my table: run the reference `verify.mjs` with your pin on mutation (3) and get `witnessed`.
